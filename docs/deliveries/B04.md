## Behavior delivered

- Each of the four B03 index adapters passes the query context and source filters to its CandidateIndex, deduplicates candidates, verifies generation/source membership through the B03 KnowledgeStore, keeps leaf chunks only, and returns existing source-backed Evidence IDs. Raw score, direction, and one-based channel rank remain in each contribution.
- Registry fusion accepts any injected `Retriever`, including a fake or future Graph retriever, without importing Graph implementation code. The fixed `k=60` RRF de-duplicates within each channel and resolves ties by chunk ID. The final top-k can differ from per-channel candidate limits.
- Channel calls honor the query deadline and may reserve against a shared `BudgetLedger`. Partial channel failures are visible in `partial` and warnings. If all channels fail, B04 raises an error. Context/generation mismatches and missing references are rejected.
- Optional reranking is injected through the frozen B00 port, capped at 40 candidates, and cannot create Evidence or path references. Original Evidence, paths, path references, contributions, and fused scores are restored. `retrieve_detailed()` returns a `RerankRecord` with query hash, input/ranked chunk IDs, returned scores, and status; it stores no query text or provider secrets.
- The B04 cloud rerank capability is available through the existing B00 `CloudReranker`, but no provider call was made. No real rerank profile is claimed as tested.
