## 正式模块

- `knowledge_weaver.models` 提供 `schema_version=1` 的严格 Pydantic DTO、判别式来源定位器、Graph/Path/Benchmark/Run 模型和 JSON Schema 导出。
- `knowledge_weaver.ports` 对齐冻结的 Parser、Chunker、Extractor、PipelineService、KnowledgeStore、CandidateIndex、GraphStore、Retriever、HybridRetriever、Reranker、EvidenceVerifier、RetrievalPolicy、AgentService、GenerationProvider、EmbeddingProvider、EvaluationRunner 接口。
- `knowledge_weaver.core` 提供固定 UUID5 命名空间与内容哈希 ID、结构化错误、配置门禁、递归日志脱敏以及线程安全的异步调用预算。每次重试独立计数；失败请求按保留 token 估算结算；取消时也会完成预算结算。
- `knowledge_weaver.providers` 提供 profile 驱动的云端 Chat、Embedding、Rerank adapter，本地 loopback Qwen Embedding adapter 和确定性 FakeProvider。正式模块不导入 `experiments/vertical_slice`。

## 配置与安全

默认 `KW_ALLOW_REMOTE=false`、`KW_MODEL_OFFLINE=true`。云端 Chat profile 读取 `KW_LLM_BASE_URL`、`KW_LLM_MODEL`、`KW_LLM_API_KEY` 并使用明确的 `/chat/completions` wire profile；云端 Embedding profile 读取 `KW_CLOUD_EMBEDDING_ENDPOINT_URL`、`KW_CLOUD_EMBEDDING_MODEL`、`KW_CLOUD_EMBEDDING_API_KEY`。调用还要求显式 external-data、budget、call 开关全部批准。

Qwen profile 读取 `KW_EMBEDDING_BASE_URL`、`KW_EMBEDDING_MODEL` 和可选的本地 `KW_LOCAL_EMBEDDING_API_KEY`，只接受 loopback 主机，使用 `/embeddings`，不读取云端凭据或云端审批开关。Rerank profile 由调用方指定请求/响应字段和分数方向，避免假定所有服务共享一种 API。

HTTP transport 禁止环境代理与自动重定向，不把请求体、URL、provider 响应正文或凭据写入错误消息。授权头、Bearer token、URL 凭据和敏感查询参数会脱敏。Fake 输出仅用于契约和离线控制流验证，不表示模型质量。

## P3 经验与边界

P3 的独立验证显示 DeepSeek 的 OpenAI-compatible Chat Completions 与本地 Qwen Embedding 可以分开配置；本地 Qwen 是 loopback 服务，不能套用云端密钥门禁。正式 B00 保留这种分离和 profile 化字段，不复用 P3 原型代码。P3 的真实调用证据仍以 P3 验证记录为准；本 B00 轮次没有调用真实 provider 或收费 API。

当前 provider 解析并保留 token usage，但没有可维护的价格表，因此不会伪造 currency cost。若预算设置 currency cap 而单次调用没有成本估计，BudgetLedger 会拒绝该调用。当前 B00 不实现解析、索引、存储、Agent、PG/Qdrant service 或真实模型质量验收。
