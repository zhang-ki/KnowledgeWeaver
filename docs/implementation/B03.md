# B03 — Storage and generation publishing

Plan version: `KW-P0-2026-11-18`; implementation attempt: `b03-indexing-attempt-001`.

## Implementation

- `storage.schema` defines PostgreSQL tables and foreign keys for corpora, sources and versions, version-document membership, facts, generation membership, leases, jobs, queries, investigations, retrieval records and answers.
- `PipelineService` composes the B01 manifest/parser/chunker and B02 extractor. It reuses documents and facts for unchanged manifest members, persists a `PARSER_EXCERPT` Evidence for each nonblank leaf span, stages immutable generation membership, builds indexes, validates references and performs a compare-and-swap on the corpus active generation.
- `PostgresKnowledgeStore` pins a query context with a lease, hydrates chunks/evidence from one ready generation and enforces source filters. `PostgresGraphStore` returns only closed graph snapshots whose mentions, relation endpoints and evidence remain visible under the source filter.
- Candidate channels are `Bm25Index`, `QdrantDenseIndex`, `SymbolIndex`, and `EntityIndex`. BM25 uses the locked tokenizer ID `kw-bm25-latin-camel-snake-cjk-char-v1`; local index artifacts are JSON and written atomically. Qdrant points carry corpus/generation/source/chunk and embedding metadata, each query applies corpus, generation and source filters before top-k, and the adapter accepts the P1 API key through a secret-valued constructor parameter.

## Limits

- Cross-store publication is ordered and compensated, not a distributed transaction. Qdrant and local artifacts are written before the PostgreSQL CAS; a failure preserves the active PostgreSQL generation and cleans known candidate artifacts/points.
- Parser caching is process-local; persisted document/chunk/fact reuse is keyed by deterministic IDs and source manifest membership.
- Physical removal of retained facts is deferred to generation GC; logical deletion publishes a new generation.
- Live PostgreSQL/Qdrant validation, fault-injection matrix, CAS race, lease/GC and full update/delete/rebuild cycle remain pending real-service acceptance because this Worktree did not receive the approved connection configuration. Do not treat the skipped service tests as a pass.
