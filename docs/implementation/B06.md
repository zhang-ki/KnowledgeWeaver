## 决定记录

1. B06 在 `agent/weights.py` 本地镜像 B07 冻结权重结构，不导入或修改 B07 评估代码。B07 尚未交付正式权重时，SEGR 明确以 `prior` profile 运行；不声称该先验优于其他策略。
2. 精确符号识别集中为一个 parser。它识别反引号名称、限定符、snake_case、CamelCase、全大写常量和函数调用；普通句首词（例如 `What`）不再误判成代码标识符。该 parser 同时用于规则路由、12 维特征、Symbol action 和确定性验证。
3. Evidence locator 中的 `python` 映射到查询合同里的来源家族 `python_repo`；PDF、DOCX 和 Markdown 沿用相同标签。没有合同标签的 locator kind 保留原值，不虚构来源家族。
4. verifier 与 answer 提示都包含 JSON 形状示例，并要求把样例 ID 替换为输入中的真实 ID。DeepSeek JSON 模式的[官方说明](https://api-docs.deepseek.com/guides/json_mode/)指出，JSON 模式应搭配明确提示和格式示例；最终真实 smoke run 使用标准 provider 路径成功返回结构化答案。
5. Graph 候选只在 Entity action 返回至少一个 seed hit 后开放；Graph 执行入口再次检查 seed，避免内部调用绕过门槛。没有 seed 时，既不生成普通 Graph action，也不生成 Graph expansion。
6. A08 关闭时，`source_match`、`independent_source_gap`、`exact_symbol`、`seed_available`、规则策略的来源提示和 source-diversity reward 均被隔离。Graph seed 资格仍作为工具安全前置条件，不参与关闭后的特征或收益。
7. 冷启动 prior 固定为 exact symbol `0.6`、source match `0.4`、other `0.2`，初始时不混入 unresolved ratio 或缺省 EMA。family 已有观测 EMA 后可按 `0.8 × prior + 0.2 × EMA` 更新；存在 learned coefficients 时使用 `0.8 × linear + 0.2 × EMA`。source-match 分类使用冻结来源匹配分值 `>=0.8`，其余不提升到匹配先验。
8. SupportMatrix 的 `conflict=true` 表示该段落处于反对一侧。Answer 只有在同一 claim 引用正向支持证据和反对证据、文本显式标记冲突且 status 为 `conflicted` 时才接受；否则降为 `insufficient`。冲突发现本身不提升收益，只有通过答案校验的双侧披露才把 `0.1 × resolved facet ratio` 加到首次补齐两侧证据的 retrieval action。
9. `QdrantDenseIndex` 的实际 embedding provider 字段为 `.provider`。真实 B06 service 装配必须把该字段绑定到当前 investigation 的 `BudgetLedger`；写入未使用的 `.embedding_provider` 会留下 ingest ledger，预算 owner guard 应继续拒绝这种装配。

## 接口与装配

`AgentServiceImpl` 实现 B00 `AgentService`。输入沿用 B00 `InvestigationRequest`，输出 B00 `Answer`。构造器接受 `KnowledgeStore`、严格包含五路工具的 Retriever map 或 factory、GenerationProvider 或 factory，可选 reranker、verifier factory、SEGR 权重和结构化 trace callback。

```python
service = AgentServiceImpl(
    knowledge_store,
    retrievers={
        "bm25": bm25, "dense": dense, "symbol": symbol,
        "entity": entity, "graph": graph,
    },
    generation_provider=lambda budget: CloudGenerationProvider(
        chat_profile, remote_approval, budget,
    ),
    weights=weights,  # 可省略；省略时显式使用 prior profile
    trace_callback=trace_sink,
)
answer = await service.investigate(request)
trace = service.get_trace(answer.investigation_id)
```

用 factory 装配时，GenerationProvider 与 Retriever 可共享本次调查的 `BudgetLedger`。verifier 和 answer generation 使用同一个已预算的 generator；LLM router 也只通过它请求候选动作。直接传入非共享 provider 时，B06 wrapper 负责预留和结算模型 token。五路工具名称固定为 `bm25`、`dense`、`symbol`、`entity`、`graph`；可额外注入 reranker。

每次调查至多 5 个 facet。没有 facet 时由 query 生成一个稳定 facet；超过 5 个拒绝。EvidenceLedger 从 KnowledgeStore hydration 已有 Evidence 和 Chunk，校验 quote/span，保留原 citation ID，同时按 `duplicate_group`（缺失时 chunk ID）合并增益覆盖。Graph path 只保留已返回、证据闭合的 relation IDs。

## 策略、状态和动作

- `FixedPolicy` 为可比较的确定性基线；`RulePolicy` 按精确符号、多跳意图、来源要求和成本启发式路由；`LLMRoutingPolicy` 只可从当前候选集合选择 action ID，坏结果或 provider 故障回退到 Rule。
- `SegrPolicy` 使用冻结的 12 维向量：bias、unresolved ratio、source match、support coverage、conflict ratio、independent source gap、recent gain EMA、lexical specificity、exact symbol、seed availability、action-family count 和 remaining-budget ratio。每次 observation 在当前 query 内更新 EMA；效用同时记录预测增益、成本、重复风险和稳定 action key。
- 冷启动先验、learned 权重和混合权重通过 `policy_profile` 区分。B06 不训练参数。`load_policy_weights(path)` 仅接受不超过 2 MB 的本地 JSON；验证 feature order、schema fingerprint、policy fingerprint、ridge/cost/stop 网格、train/dev 标记和 action 样本计数。
- 候选包括 BM25、Dense、Symbol、Entity、Graph、可选 rerank，以及每 facet 最多一次的有界 query expansion。Graph hops 被限制为 1–2，edge 上限不超过 200；候选最多 30 个。
- verifier 对 facet/evidence 对生成 `SupportMatrix`，可返回 support `0 / 0.5 / 1` 和 conflict。确切代码标识符在原文中出现时可确定性支持；其他判断通过共享 generator。返回重复/未知 pair 会被拒绝，缺行保守记为 unsupported。
- 状态记录 facet coverage、source family、conflicts、路径、最近 action、gain EMA、预算和停止状态。停止包含充分证据、连续无增益、低期望增益、动作耗尽、硬预算、deadline 与取消；关闭动态软停止不会关闭硬上限。

## 预算、安全与答案闭合

- 每个 action、LLM call、rerank、verifier 和最终 citation validation 都经过预留、结算和 deadline 检查；retrieval 后的 evidence/chunk hydration 也在 deadline 内。重试消耗新预留。
- Dense usage 缺失时，B06 至少按候选估算 token 收费，并同步收紧后续 generation 的 token 预算。未知计量不会记为零成本。
- `enable_graph`、`enable_expansion`、`enable_reranker`、`enable_sufficiency_stop`、`enable_dynamic_stop`、`enable_source_features`、`enable_learned_gain`、`enable_cost` 和 `enable_relation_semantic_verification` 分别控制各自能力；未知 flags、非 boolean flags 和超出冻结网格的参数被拒绝。
- 没有支持证据时返回无 claims 的 `insufficient`，不调用 answer generation。answer claims 中的 evidence ID 必须在提供给模型的有效 Evidence 集内，并通过 `KnowledgeStore.validate_citations`；relation ID 必须属于已提供的闭合路径。
- trace 只含结构化 action、candidate score/reason、observation reward/usage、policy fingerprint/profile 和 stop reason，不保存 prompt 或推理文本。trace 默认保存在 service 实例内；需持久化时由调用方传入 callback。
