## 数据路径与算法

夹具由 `fixture_pdf.py` 生成真实 PDF 文件；PDF 头含规范的二进制标记，内容流用合法 NUL 空白使 Git 识别为二进制，隔离解析器从未压缩 ASCII 文本层读取段落并记录 page/block。Python 夹具用 AST 定位 `EvidenceRecord.span: SourceSpan`，代码引用保留 1-based 行号。当前解析器只支持仓库自生成的一页、未压缩文本 PDF；它不是一般 PDF 解析器。当前绑定工作树没有 Docling，未安装依赖，也未重新执行 P1 Docling gate。

每个非空段落/代码行生成 leaf Chunk、`PARSER_EXCERPT` Evidence 和源定位。Evidence 的 quote 与 chunk 文本一致，使用冻结 UUID5 namespace、SHA-256 和 UTF-8。文本侧精确合成句生成 `MANUAL` 关系，Python 注解生成 `STATIC_ANALYSIS` 关系；夹具内 `EvidenceRecord` 与文本 `Evidence` 的合并依据写入 manifest，避免隐式跨源同名合并。两跳链为 PDF `IngestionPipeline USES Evidence` → Python `Evidence CONTAINS SourceSpan`，路径携带两边 relation/evidence ID，并经来源类型及引用闭合检查。

初检提供独立 BM25 和 Dense 通道；BM25 使用确定性 TF/IDF 公式，离线 Dense 使用版本化 SHA-256 token-sign Fake 向量。公开 prior 为 exact symbol=0.6、来源匹配=0.4、其他=0.2；每动作记录 12 维特征、估计成本/效用、候选动作、观测到的新 Evidence、收益代理、EMA、预算余量和停止原因。跨源问题先 Dense，再在检索到图种子且效用超过 tau=0 后执行 Graph；硬预算、deadline、无图种子、无证据、冲突、超时和无效引用均有确定行为。收益代理是“新增且可闭合的夹具证据”，不是语义正确率或真实 SEGR 效果。

DeepSeek 生成接口保留 JSON claim、evidence_ids 与 relation_ids 校验路径；Qwen embedding 适配器保留 query/document 模式。两者只接受显式 endpoint/model/本地 key，并额外要求外发批准、预算批准、非零费用上限、调用显式开关以及 `KW_ALLOW_REMOTE=true`、`KW_MODEL_OFFLINE=false`。当前这些条件未满足；本轮未发出任何外部请求，Fake 结果不作为真实模型效果。

`PostgresEvidenceStore` 使用 P3 前缀隔离 schema 持久化 Source/SourceVersion/Document/Chunk/Provenance/Evidence/Entity/Relation 与 generation membership；`QdrantDenseIndex` 使用 P3 前缀 collection、确定 point ID 和 generation filter。另有 `service_probe.py` 可在服务与本地 Python 驱动可用后执行本任务专属资源探针。当前未创建数据库 schema 或 collection。离线 run 已把合成 Evidence 和 Fake 向量写到本地 JSON；这不等同 PG/Qdrant 实测。
