# 产品与研究定位

KnowledgeWeaver 面向需要共同理解论文、代码和技术文档的开发者、研究者与知识工作者。支持仓库理解、论文分析、技术调查、跨源问答和知识管理；不限定学习辅导或某一行业。企业知识管理是应用方向，MVP 不承诺企业级权限与多租户。

核心研究问题：在给定资源预算内，如何根据来源类型、当前证据缺口和观察到的检索收益，选择下一步动作，减少无效检索并取得充分、可追溯的证据？

唯一主要算法贡献候选：Source-aware Evidence Gain Routing，简称 SEGR。用可解释、低维的收益预测器与硬预算控制，为每轮动作估计“新增支持/补齐缺口/处理冲突”的收益与成本。RRF、BM25、Dense、Cross-Encoder 与图遍历是基础组件，组合本身不作为创新结论。SEGR 的新颖性与有效性需要文献对比和实验检验，不预先宣称学术首创。

MVP 输入四源：Python 静态 AST，文本型 PDF（含普通表格），DOCX 正文与表格，Markdown 结构。输出按 claim 组织的回答、可定位 Evidence、调查动作记录、未解决问题和实际预算消耗。非目标：OCR、完美复杂公式/版面恢复、动态执行/完整调用图、自动全网抓取、模型训练大工程、MCTS/RL、生产多租户与公网部署。

规划目标为约一个月 MVP，按可用人力和授权条件估算，非工期保证。周1 完成环境/协作验证/纵切片与 B00；周2 B01/B02/B07.prep/B03；周3 B04/B05/B06；周4 B07.final/B08。外部授权、人工 Gold、硬件不足可能延长。超时优先缩减扩展功能，不能跳过基础门禁或伪造实验。

资源边界：单用户本机，最多 10,000 leaf chunks、5,000 entities、20,000 relations；每文件 20 MiB、单 Python 文件 2 MiB、总 500 文件。默认图 2 跳、200 边；单调查最多 6 轮/12 工具调用/8 LLM 调用/12,000 total tokens/60s。数量是保护上限，不是速度保证。
