| **U-01** | **启动流程过于繁琐，缺少一键启动 KW / KS 能力**（需多窗口配置环境变量，易出现 RabbitMQ 占位密码 `403`、UUID 未加引号报错、`KW_ALLOWED_ROOTS` 不存在；用户希望一键启动 KW 服务与 KS 服务，并确认容器是否仍需手动启动） | 现有 `infra/start-local.ps1` 未自动拉起 Docker 容器、未自动读取 `.kw/secrets/compose.env` 与 `KnowSphere/.env`，也未集成 `mq-bridge` 及 KnowSphere 栈启动。 | **已实现并实测通过**（统一入口均收口至 `D:\agent\`：KnowSphere 目录下提供 `D:\agent\KnowSphere\scripts\{start-ks,stop-ks,start-all,stop-all}.ps1`，KnowledgeWeaver 目录下提供 `D:\agent\KnowledgeWeaver\scripts\{start-kw,stop-kw}.ps1` 及 `local.env.example`；自动拉起 Docker Desktop 与全部容器，自动识别 B08 代码目录、加载本地密钥与 RabbitMQ 凭据并建目录，实测 6 容器 + FastAPI + Streamlit UI + `kw mq-bridge` 联合启动与进程树清理全部通过） | 如需本机 Embedding / 本地大模型或指定 `KW_CORPUS_ID`，复制到 `D:\agent\KnowledgeWeaver\.kw\secrets\local.env` 后下次运行一键脚本自动加载即可。 |
| **U-02** | **KnowSphere 前端（`http://127.0.0.1:3000/`）打开报 `会话已失效或未认证 (401)`** | 前端在 `VITE_API_MODE=live` 下通过页面右上角 `Bearer Token` 输入框发送 `Authorization: Bearer <token>`，而后端 `DevActorAuthenticationFilter`（`local`/`test` profile）原先仅识别 `X-Dev-User-Subject` 请求头，未解析开发 `Bearer` 令牌。 | **已修复并验证**（修改 `DevActorAuthenticationFilter.java` 支持 `Bearer oidc\|...` / `Bearer dev:...`，已重建重启 `knowsphere-backend` 容器；无凭据仍返回 `401`，带 `oidc\|live-e2e-user` 返回 `200`） | 保持仅在 `local`/`test` profile 启用，生产 `prod` profile 不注册该过滤器；可在前端本地模式增加更明确的使用提示。 |
| **U-03** | **手动复制进 `my_docs` 的 `functions.py` 在 KnowSphere 前端知识库列表看不到，且提交任务必须勾选知识库** | 1. 两端文件/知识库当前独立存储，KnowSphere 与 KnowledgeWeaver 的 `source_ids` 尚未建立自动同步与映射。<br>2. KnowSphere 创建 Q&A 任务强制校验 `knowledgeBaseIds` 非空（平台多租户权限范围校验）。<br>3. `functions.py` 在 KW 仅完成 Register（`indexed: false`），尚未执行入库索引。 | **已知架构边界**（引导在 KW UI 点击 `Ingest` 后，可在 KnowSphere 勾选任意已授权知识库触发检索） | 后续在 KnowSphere 上传资源时增加向 KnowledgeWeaver 的受控同步与 `knowledgeBaseId -> source_id` 映射。 |
| **U-04** | **KW UI（`http://127.0.0.1:8501`）操作引导名称与界面按钮不一致** | 文档/指引中误写为 `Start Ingestion`，实际界面 [ui/app.py](file:///D:/codex/1190/KnowledgeWeaver/src/knowledge_weaver/ui/app.py#L284) 中按钮名称为 **`Ingest`**。 | **已核对澄清** | 统一用户手册与指引中的按钮名称为 `Ingest` / `Check Job`。 |
| **U-05** | **较大文件入库过程中 `Refresh Health` / `/v1/jobs` 偶发 `timed out`，再次点击后恢复** | `kw serve` 为单进程单事件循环（Uvicorn）。在入库 95KB 的 `functions.py` 时，`pipeline.ingest()` 内的 AST 解析、分块（`chunker.split`）与索引构建等同步 CPU 操作阻塞了主事件循环，导致并发进来的 `/healthz`、`/readyz` 与 `/v1/jobs/{id}` 暂时超时；待同步阶段结束进入 `await` 后恢复响应。另外整个 `ingest()` 放在单个数据库事务中，大文件耗时较长期间任务状态持续显示 `running`。 | **已定位，暂未改代码** | 1. 将 `parser.parse_detailed`、`chunker.split`、BM25/Symbol/Entity 索引构建等 CPU 密集步骤放入 `asyncio.to_thread(...)`。<br>2. 考虑在 Job 状态中暴露阶段进度（parsing / extracting / embedding / indexing），改善大文件入库可观测性。 |
| **U-06** | **95KB `functions.py` 入库最终失败，报 `PROVIDER_UNAVAILABLE (category=timeout)`** | `QdrantDenseIndex.publish()`（[dense.py](file:///D:/codex/1190/KnowledgeWeaver/src/knowledge_weaver/indexing/dense.py)）原先将整库所有叶分块文本合并为**单次** HTTP POST 发给本地 `Qwen3-Embedding`，且 `LocalQwenProfile.timeout_seconds` 默认仅 30 秒，导致较多分块在单次请求内超时。 | **已修复**（`dense.py` 改为每批 16 条分批 Embedding；`runtime.py` 将本地 Embedding 单次超时提高到 60s，入库配额提升至 `max_llm_calls=200` / `max_total_tokens=500000`） | 重启 `kw serve` 后在 UI 重新点击 `enneuro` 的 `Ingest` 验证即可。 |
| **U-07** | **KnowSphere 需要正式的注册/登录业务替代开发期 Bearer Token**（QQ 邮箱发送验证码 + 安全存储用户信息 + 与组织/团队体系打通） | 当前 KnowSphere 仅在 `local`/`test` profile 提供 `DevActorAuthenticationFilter`，通过开发请求头或临时 Bearer 令牌识别用户，缺少正式账号注册、邮箱验证码校验、密码哈希存储与会话签发。 | **已实现并实测通过**（新增 Flyway `V4` 迁移与 `com.knowsphere.auth` 后端模块、纯 Java 21 SSL QQ 邮箱 SMTP 发送器、BCrypt 密码哈希 + 加盐 SHA-256 验证码与会话令牌存储、`ks_session` HttpOnly Cookie 鉴权、组织/团队邮箱邀请及注册自动入组、前端 `AuthPanel` 与 `OrganizationDetailPage` 邮箱邀请 UI；后端 49/49、前端 46/46 测试全绿，已重建容器并完成 `2959129749@qq.com` 真实 QQ SMTP 发信与频率限制实测） | 生产环境部署 HTTPS 时将 `.env` 中 `KNOWSPHERE_AUTH_COOKIE_SECURE` 设为 `true`；若后续需要找回密码/重置密码，可复用 `email_verification_codes` 表的 `purpose` 字段扩展 `RESET_PASSWORD`。 |
